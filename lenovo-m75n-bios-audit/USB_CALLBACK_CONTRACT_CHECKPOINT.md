## Dispatch path
Uhcd entry 3A8 invokes 1440 (old 14D0). The shared allocator creates a zeroed arena (8CC8, page zeroing at 8D54) and callback structure 0x88 bytes. 1764 loads its address, 17A1–1808 sets function pointers +08,+10,+18,+20,+28,+30,+38,+40,+60,+68,+70, 1813 sets +00, 181D installs protocol GUID 2ad8e2d2-2e91-4cd1-95f5-e78fe5ebe316 (at CE00). Uhcd does not set +78 in that sequence.
UsbRtDxe DEPEX requires this same GUID AND 13a3f0f6-264a-3ef0-f2e0-dec512342f34, identical all releases. Entry 354 finds the protocol (GUID old 1C3D0/new 19650), stores shared data pointer, and on successful lookup sets callback+78 to routine 674 (3DB). This occurs for both outcomes of test of shared field +65C. The same instructions and callback address occur in 124 and 132/133; RIP data placement differs. This establishes intended initialization and narrows P2-20 fallback applicability: if callback is populated, Uhcd continues to invoke it. It does not establish actual DXE ordering beyond DEPEX, successful init, or every potential pre-registration call.
New Uhcd wrapper 3538 skips work if callback+78 zero; old 35EC invokes SMM Control2 fallback (P2-15/20). Separate 34C4 SMI helper still exists; three direct calls at 2015,23CA,2523 pass their statically prepared request fields through the new SMM filter. This was checked by comparing constant writes in each basic block against five records at 1C818 and the actual comparison loop in 1AFE0. No incompatible direct SMI caller found in this narrow set. Does not validate every dynamic request, state, or alternate route.
