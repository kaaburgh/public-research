ThermalMode (133) reads Setup at RVA438/44E; 4A7 passes address of local Setup buffer to BAC and D31 reads byte +8 when the indicated flag is zero. The value is placed in the DPTC SSDT-related path at D7D; this supports treating Performance Mode as a real potential thermal-policy confounder. No measured wattage or noise effect. P2-63 shows the same ThermalMode and ThermalModePei bodies in 1.32/1.33. Existing modes are not new in 1.33. 

Boot Mode and Boot option filter share Setup offset193. Factory value is Auto/UEFI and Legacy. But SetupLoadDefault 40A captures OS Optimized Defaults (offset3D) and 683–6B1 uses it to choose CSM, boot filter and priority values; if nonzero, forces CSM disabled and UEFI-only. This may override default offset193 after a reset if that path executes; not a proof of actual boot-mode change. TPM interface offset7A is unconditional GrayOutIf True in native IFR, so a raw difference in stored value is not proof that actual transport changes.
