# Methodology (v2, 2026-11-26)

## Reproduce extraction
Use a dedicated local work directory, never modify source files. Verify SHA-256 first. Copy to 124.rom, 132.rom, 133.rom. Run UEFIExtract_A75 on each:
```sh
for v in 124 132 133; do
  /path/to/UEFIExtract_A75 "$v.rom" all >"$v.extract.log" 2>&1 || exit 1
done
python3 tools/inventory.py 124.rom.dump 132.rom.dump 133.rom.dump -o regenerated.tsv
python3 tools/compare_inventory.py data/inventory.tsv regenerated.tsv
python3 tools/audit_verify.py data/inventory.tsv 124.rom.dump 132.rom.dump 133.rom.dump
python3 tools/flashmap_model.py 124.rom.dump 132.rom.dump 133.rom.dump
```
Run from a directory where paths resolve (or use absolute script/data paths). Extract reports and original .rom.dump tree; don't flatten duplicate names. inventory.py independently enumerates the historical FFS leaf profile. compare_inventory.py checks key coverage and payload hash/size multisets (known hashes only for public redacted reference). audit_verify.py verifies executable hashes and relocation classifications. All three checks passed on corrected private reference. Keep diagnostics; unexpected nonzero exit is a blocker. See REPRODUCTION.md. Generated local files may contain private hashes; do not commit them.

## Inventory and normalization
For each FFS file identify GUID, subtype, Text, occurrence and full hierarchy (FV GUID/path + sibling index); recurse into compressed/guid-defined sections and embedded volumes. Use nearest enclosing FFS owner. Enumerate leaf payloads (body.bin) with section subtype and occurrence; raw files without sections separately. Exclude live NVAR and pad bytes from module inventory, inventory them separately as regions. Record absent vs zero-length, sizes, SHA-256. Compare three versions. Match duplicate GUIDs with path, content hashes and neighboring identities; arbitrary occurrence order is a hypothesis. The reconstructed generator includes historical embedded raw/container leaves and orders by label lineage before numeric ordinal. It reproduces the 2256 keys; PcdPeim pairing corrected; see E15 in private Evidence and REPRODUCTION.md. For arbitrary ROMs, ambiguous duplicate lineage still requires manual checking. Audit coverage against FV/FFS extraction report, AMD directories and raw byte map.

PE/TE: parse header and section table; translate RVA via virtual address and raw pointer; TE stripped delta = StrippedSize-40. Subtract ImageBase from HIGHLOW (type 3, 32-bit) and DIR64 (type 10, 64-bit) targets modulo width; skip ABSOLUTE; zero ImageBase. Do not silently skip unsupported relocation types or invalid bounds. Compare full normalized payload, not just .text. Two discrepancies were resolved by examining the raw TE headers: only ImageBase byte at +0x10 differed. B08 closed. PE/TE .text equal does not imply data/metadata equal. Don't normalize timestamps without separate attribution. For TE disassembly use correct machine type; PE objdump -d -M intel; TE raw objdump -D -b binary -m i386 or i386:x86-64 with explicit ranges, map file offsets to RVA. Record coordinate convention and image version for every claim.

## Semantic analysis
Use `python3 tools/instruction_diff.py old.efi new.efi -o diff.json` for deterministic candidate matching. It disassembles PE via objdump and TE by machine/section/RVA; retains original instructions in JSON, including addresses and bytes. Reports int3 chunks, not verified functions. Extract sections and compare instruction sequences. Split by actual unwind/runtime function table or verified function boundaries; int3/nop heuristics are search aids. Normalize branch targets/RIP displacements only for candidate matching; then resolve each changed reference, immediates, data tables, protocol GUIDs, DEPEX, callbacks and callsites. Similarity is not proof. For Setup size pattern BE 01→C1 01, verify all changed bytes and stack/unwind adjustments. For HII extract via ifrextract-rs module.efi; compare IFR forms, questions, varstores, option encoding, conditions/defaults and callbacks; question ID shifts not semantic proof. Verify exact default bytes from StdDefaults, MfgDefaults separately. Use GetVariable/SetVariable GUID and size to validate references.

NVAR: inspect Full/Data/Link/Invalid state, GUID index table and linked records; resolve newest valid chain, do not assume highest file index is active; cross-check both stores; do not export secrets/identifiers. Decode EFI_LOAD_OPTION: attrs u32, path len u16, UTF16 terminator, device path node lengths and end marker; verify actual ESP separately. For AMD APCB parse header size, UniqueApcbID/checksum, group/type, token descriptor and packed values. Compare same variant/copy; checksum sum(payload[0:SizeOfApcb]) mod256=0. Compare live override separately from factory. Cross-reference token writers and consumer code; never infer actual UMA allocation from token alone. Microcode: inspect PSP/BHD directories, equivalence IDs, patch revisions/date/length, exact payload hash; compare Linux runtime microcode and official security bulletins, do not infer slowdown/CVE from revision alone. ACPI: checksum-validated static tables, signature, length, OEM IDs; compare table sets and multiplicities; dynamic tables require live acpidump/iasl.

## Evidence and completion
One row per section and version pair: stable key GUID/instance/section/section_instance, hash/size, observed diff, addresses, instruction/data change, interpreted effect, alternative explanations, confidence, blocker, next test. Preserve historical conclusions with superseded-by ID. Use exact byte equality, relocation-only, explained change, partial, candidate, open, added/removed, blocked (static or runtime). A candidate pattern is not a closed module. A semantic closure requires attribution of every changed code/data group or explicit residual, including DEPEX; runtime closure requires controlled hardware data. Scope claims narrowly. No operation on real flash or direct variable writes in static analysis.

## Platform inspection (v3 extension)
Run the commands in PLATFORM_REPRODUCTION.md. AMD directory offsets are specific to these images; validate signature, Fletcher-32 and address bounds before mapping. Compare metadata and payloads independently, do not interpret fuse sentinel as a file offset. APCB header/group/type checks plus checksum and CBS token widths; retain unknown fields. NVAR inspector resolves selected name/GUID roots through A75-reported links, reports ambiguity rather than picking the last filename; it is not a standalone NVAR decoder and does not identify active store. EFI_LOAD_OPTION FilePathList may include multiple packed paths, each with an End Entire node. Distinguish generic structural validity from implementation-specific BDS policy. IFR comparison drops only the version/SHA header; conditions and IDs preserved. Raw coverage partitions union of validated physical intervals and assigns overlaps deterministically, retaining both label sets. Raw physical diffs are not module semantic diffs. No raw firmware or private reports in Git.
