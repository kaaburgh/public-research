# Methodology (v1, 2026-11-26)

## Reproduce extraction
Use a dedicated local work directory, never modify source files. Verify SHA-256 first. Copy to 124.rom, 132.rom, 133.rom. Run UEFIExtract_A75 on each:
```sh
for v in 124 132 133; do
  /path/to/UEFIExtract_A75 "$v.rom" all >"$v.extract.log" 2>&1 || exit 1
done
python3 tools/audit_verify.py data/inventory.tsv 124.rom.dump 132.rom.dump 133.rom.dump
```
Run from a directory where paths resolve (or use absolute script/data paths). Extract reports and original .rom.dump tree; don't flatten duplicate names. Script only verifies PE/TE hashes and relocation classifications for existing ledger records, not completeness of enumeration. Nonzero exit for discrepancies is expected for the two known rows. Keep diagnostics; do not discard differences.

## Inventory and normalization
For each FFS file identify GUID, subtype, Text, occurrence and full hierarchy (FV GUID/path + sibling index); recurse into compressed/guid-defined sections and embedded volumes. Use nearest enclosing FFS owner. Enumerate leaf payloads (body.bin) with section subtype and occurrence; raw files without sections separately. Exclude live NVAR and pad bytes from module inventory, inventory them separately as regions. Record absent vs zero-length, sizes, SHA-256. Compare three versions. Match duplicate GUIDs with path, content hashes and neighboring identities; arbitrary occurrence order is a hypothesis. The historical inventory included some container/embedded raw rows and used instance order, so a new generator may not exactly reproduce the count. Audit coverage against FV/FFS extraction report, AMD directories and raw byte map.

PE/TE: parse header and section table; translate RVA via virtual address and raw pointer; TE stripped delta = StrippedSize-40. Subtract ImageBase from HIGHLOW (type 3, 32-bit) and DIR64 (type 10, 64-bit) targets modulo width; skip ABSOLUTE; zero ImageBase. Do not silently skip unsupported relocation types or invalid bounds. Compare full normalized payload, not just .text. Reconstructed implementation differs from old classification in two rows; inspect relocation targets manually. PE/TE .text equal does not imply data/metadata equal. Don't normalize timestamps without separate attribution. For TE disassembly use correct machine type; PE objdump -d -M intel; TE raw objdump -D -b binary -m i386 or i386:x86-64 with explicit ranges, map file offsets to RVA. Record coordinate convention and image version for every claim.

## Semantic analysis
Extract sections and compare instruction sequences. Split by actual unwind/runtime function table or verified function boundaries; int3/nop heuristics are search aids. Normalize branch targets/RIP displacements only for candidate matching; then resolve each changed reference, immediates, data tables, protocol GUIDs, DEPEX, callbacks and callsites. Similarity is not proof. For Setup size pattern BE 01→C1 01, verify all changed bytes and stack/unwind adjustments. For HII extract via ifrextract-rs module.efi; compare IFR forms, questions, varstores, option encoding, conditions/defaults and callbacks; question ID shifts not semantic proof. Verify exact default bytes from StdDefaults, MfgDefaults separately. Use GetVariable/SetVariable GUID and size to validate references.

NVAR: inspect Full/Data/Link/Invalid state, GUID index table and linked records; resolve newest valid chain, do not assume highest file index is active; cross-check both stores; do not export secrets/identifiers. Decode EFI_LOAD_OPTION: attrs u32, path len u16, UTF16 terminator, device path node lengths and end marker; verify actual ESP separately. For AMD APCB parse header size, UniqueApcbID/checksum, group/type, token descriptor and packed values. Compare same variant/copy; checksum sum(payload[0:SizeOfApcb]) mod256=0. Compare live override separately from factory. Cross-reference token writers and consumer code; never infer actual UMA allocation from token alone. Microcode: inspect PSP/BHD directories, equivalence IDs, patch revisions/date/length, exact payload hash; compare Linux runtime microcode and official security bulletins, do not infer slowdown/CVE from revision alone. ACPI: checksum-validated static tables, signature, length, OEM IDs; compare table sets and multiplicities; dynamic tables require live acpidump/iasl.

## Evidence and completion
One row per section and version pair: stable key GUID/instance/section/section_instance, hash/size, observed diff, addresses, instruction/data change, interpreted effect, alternative explanations, confidence, blocker, next test. Preserve historical conclusions with superseded-by ID. Use exact byte equality, relocation-only, explained change, partial, candidate, open, added/removed, blocked (static or runtime). A candidate pattern is not a closed module. A semantic closure requires attribution of every changed code/data group or explicit residual, including DEPEX; runtime closure requires controlled hardware data. Scope claims narrowly. No operation on real flash or direct variable writes in static analysis.
