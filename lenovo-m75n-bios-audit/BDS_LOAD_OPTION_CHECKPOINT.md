## Change

It also tries lowercase Boot%04x after uppercase Boot%04X returns EFI_NOT_FOUND (strings c6df8/c6e10). The function is still present in the same relative table slot (124 c6f20→3fac, 132 c6fc0→4078); precise dispatch condition unresolved.

132 function 9768 reads BootOrder and each Boot%04X using global variable GUID 8be4df61-93ca-11d2-aa0d-00e098032b8c (c4d28), then new helper call at 983c. If false, SetVariable at 9862 with same global GUID (c47f0), attributes/size/data zero, then FreePool at 986f and skip. Old 9740 parsed without this call. 132 also frees empty result allocation at 99cb. Caller 9b5c in function 9b30. This is added coverage of pre-existing deletion policy, not entirely new deletion mechanism. No direct claim about BootOrder rewrite in these routines. SetVariable result ignored. 132 and 133 helper bytes 3fb0..4077 and 6e24..6ef1 exact; 4078..4209 and 9768..99e2 each four changed RIP references, targets +e0, all other instructions same.

## Applicability to owner capture

Helper checks minimum path-list length 4, record size and description bounds, per-path returned lengths vs remaining list and final End Entire node. Existing helper 6e24 accepts types 1,2,3,4,5,7f (table c75bc) and length >=4 for non-final nodes, total walk <=64 KiB; helper 6ea0 computes path length. These helpers have no remaining-buffer size parameter; this is not proof of robust handling of malformed records. A conservative bounded well-formed-data model checks the record header, UTF16 description termination, permitted node types and lengths, final End Entire. Model is not an emulator of malformed-input behavior. Use tools/boot_option_model.py on A75 AFU NVAR store directories; existing raw-chain analysis P2-104/105 identifies terminal Full/Data records. No raw payloads/IDs/descriptions published. Tested local capture: store1 9/9 referenced records pass; store2 10/10 pass. Counts refer to instances, not 19 unique entries. Store2 is conditionally selected (P2-106); actual live/after migration state untested. This reduces risk for captured valid records, not guarantee that all Boot#### survive migration or that BDS selects same path. Other BDS PE changes, exact BDS policy/BootFlow dispatch remain open.
